# RAG 생존 및 신뢰성 강화를 위한 정밀 수술 계획 (2026-03-12)

본 계획은 현재 시스템의 '근거 박약' 문제를 해결하고, SKMS 원문과의 연결성을 100% 보장하기 위한 하드코어 고도화 로드맵입니다.

## 1. 수술 목표 (Surgical Objectives)
- **무결성**: 모든 생성 문장의 SKMS 원문 근거 확보.
- **정밀도**: 검색 결과 상단에 엉뚱한 정보가 배치되는 현상 차단.
- **투명성**: 사용자가 AI 답변의 근거를 즉시 시각적으로 확인 가능.

## 2. 세부 수술 프로토콜 (Protocols)

### Surgery 1: 하드-커플링 인용 (Attribution Enforcement)
- [ ] **프롬프트 강제화**: `Copywriter`가 생성하는 모든 문장 끝에 `(Ref: quote_id)` 삽입 명령 추가.
- [ ] **파싱 및 검증 로직**: `generator.py`에서 인용 태그를 추출하고, 제공된 `hits` 목록에 존재하는 ID인지 교차 검증.
- [ ] **자동 반려 시스템**: 인용이 누락되었거나 허위 인용 시 `Reviewer` 단계에서 재생성 강제.

### Surgery 2: Cross-Encoder Reranker 적용 (Precision Retrieval)
- [ ] **리랭킹 파이프라인**: 1차 Hybrid Search(20개) -> Reranker(상위 5개) 순으로 정제.
- [ ] **의미적 일치도 평가**: 질문과 원문 조각 간의 실제 의미 유사성을 수치화하여 최적의 컨텍스트만 LLM에 전달.

### Surgery 3: 실시간 팩트체크 모드 (UI Transparency)
- [ ] **Source Metadata 확장**: API 응답에 인용된 문장의 원문 텍스트 전체와 전후 문맥 정보를 포함.
- [ ] **Fact-Check Overlay**: Netlify UI에서 슬라이드/카드 내 인용 표시 클릭 시 원문 팝업 렌더링.

## 3. 집행 일정
- **Phase 1 (현재)**: 수술 1 (하드-커플링 인용) 집행 및 검증.
- **Phase 2**: 수술 2 (리랭커 도입)를 통한 검색 질 향상.
- **Phase 3**: 수술 3 (UI 투명성) 완성 및 최종 임상 테스트.
