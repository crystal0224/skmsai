# SKMS Company Builder — Game Mechanics Overhaul

**Date**: 2026-03-19
**Status**: Approved
**Scope**: `public/parktycoon.html` — 경영관리 메커닉, 시간/피드백, 엔딩 리포트
**Sub-projects**: 3개 (독립 구현 가능, 순서대로 진행 권장)

## Problem

1. **경영관리 메커닉이 너무 얕음** — 성과평가(전원 S 가능), 보상(1.1x/1.2x 클릭), SKMS 정책은 "켜면 좋아지는 스위치"
2. **적극적 개입 수단 부족** — 더 좋은 결과를 만들 전략적 선택지가 없음
3. **SKMS 철학이 게임에 안 녹아듬** — 딜레마 속에서 SKMS 원칙을 체감하며 학습해야 함
4. **게임이 너무 길고 피드백이 약함** — 40분+ 플레이, 선택→결과 극적 연출 부재
5. **엔딩 리포트가 세로로 길고 가독성 나쁨** — 스크롤 피로, 정보 밀도 낮음

## Design Philosophy

**SKMS 학습 = 라벨 없이 체감**: 선택지에 "이것이 인간중심입니다" 표시하지 않음. SKMS 원칙을 따른 선택이 장기적으로 좋은 결과를 만들고, 엔딩 리포트에서 "당신의 선택은 SUPEX 추구와 78% 일치했습니다" 같은 피드백으로 사후 학습.

## Sub-project 1: 경영관리 메커닉 강화

### 1A. 성과평가 — 상대평가 강제배분

**현재**: 직원별 S/A/B/C/D 자유 선택, 제한 없음
**변경**: 등급별 쿼터 제한 (강제배분)

| 등급 | 쿼터 | 효과 |
|------|------|------|
| S | 최대 20% | will+10, hap+15, bonus$50 |
| A | 최대 30% | will+5, hap+8, bonus$30 |
| B | 제한없음 | will+0, hap+0, bonus$0 |
| C | 최소 10% | will-5, hap-5 |
| D | 최소 10% | will-10, hap-15, PIP 발령 |

**UI 변경**:
- 패널 상단에 쿼터 현황 바 표시: `S: 1/2 | A: 2/3 | B: ∞ | C: 0/1↑ | D: 0/1↑`
- 쿼터 초과 시 해당 등급 버튼 비활성화 + "초과" 빨간 표시
- C/D 최소 쿼터 미달 시 "확정" 버튼 비활성화 + "C/D 등급 부족" 경고
- 전체 평가 완료 후 "✅ 평가 확정" 버튼 클릭 → 일괄 적용

**성과평가 임시 상태 관리**:
- 등급 버튼 클릭 시 즉시 적용하지 않고 `pendingGrades = {workerId: gradeObj}` 맵에 저장
- 쿼터 현황은 pendingGrades 기준으로 실시간 업데이트
- "✅ 평가 확정" 클릭 → pendingGrades를 순회하며 일괄 적용 (will/hap/bonus/PIP)
- 패널 닫기(확정 없이) → pendingGrades 폐기, 아무 효과 없음
- 보너스 비용: `G.money -= bonus` (회사에서 직원에게 지급하는 비용)

**SKMS 딜레마**: D등급 준 직원에게 면담을 추가로 하면 회복 기회(PIP+역량 개발), 안 하면 높은 퇴사 확률. "인간중심 = 저성과자에게도 성장 기회"를 체감.

### 1B. 보상관리 — 정책 기반 전략 선택

**현재**: 직원별 1.1x/1.2x/1.3x/동결 선택
**변경**: 3가지 보상 전략 중 택1 (분기 회의 시에만 변경 가능, 15일마다)

**전략 변경 규칙**:
- 보상관리 패널은 항상 열 수 있지만, 전략 변경은 **분기 회의 기간에만** 가능
- 분기 회의 외에는 현재 전략이 읽기 전용으로 표시
- 전략 적용 시 기존 개인별 `salaryLevel`은 1.0으로 리셋 (전략이 개인 협상을 대체)

**전략 옵션:**

| 전략 | 아이콘 | 효과 | SKMS 연결 |
|------|--------|------|-----------|
| 성과연동형 | 🎯 | S/A: bonus$80/$40, C/D: 동결. 에이스 유지↑, 시니크 불만↑ | SUPEX 추구 — 탁월한 성과에 보상 |
| 균등분배형 | ⚖️ | 전원 will+3, hap+5. 조직 안정↑, 에이스 이탈 위험(10%/분기) | 인간중심 — 모든 구성원 존중 |
| 역량투자형 | 🌱 | 전원 capability+8, bonus 없음. 장기 성장↑, 단기 만족↓ | VWBE — 자발적 두뇌활용 역량 강화 |

**UI**:
- 현재 직원 리스트 대신 **3개 전략 카드** 가로 배치
- 각 카드: 아이콘 + 이름 + 효과 요약 + "현재 적용 중" 배지
- 카드 클릭 → 확인 다이얼로그 → 즉시 전원 적용
- 하단에 인건비 총액 + 전략별 예상 영향 미리보기

### 1C. 이벤트 딜레마 — SKMS 히든 보너스

**현재**: 이벤트 3개 선택지, 정책 프리리퀘짓 있지만 SKMS 원칙과 명시적 연결 없음
**변경**: 기존 15개 이벤트의 선택지에 SKMS 원칙 기반 장기 효과 추가

**원칙**:
- **인간중심 선택**: 단기 비용↑, 장기 직원 지표↑↑ (예: 번아웃에 강제휴가)
- **성과 추구 선택**: 단기 매출↑, 장기 직원 이탈 위험↑ (예: 번아웃 무시)
- **통합 선택**: 특정 정책+시설 필요, 양쪽 다 좋음 (예: VWBE+Wellness로 자동 치유)

**구현**: 기존 `EVENTS` 배열의 각 choice에 `skmsTag` 필드 추가 (내부용, UI 미표시):
```
skmsTag: 'human_centered' | 'supex' | 'vwbe' | 'social_value' | 'rational'
```
- 선택 시 `G.skmsChoices` 배열에 기록 → 엔딩 리포트에서 분석
  - 데이터: `{eventId: string, choiceIdx: number, tag: string, day: number}`
  - 게임 상태 초기화 시 `G.skmsChoices = []` 추가 (createInitialState)
- 각 choice에 `delayed` 필드 추가: `{days: 3-5, event: 'followup_id'}` → 후속 이벤트 트리거

**새 게임 상태 필드** (createInitialState에 추가):
- `G.skmsChoices = []` — SKMS 태그 기반 선택 기록
- `G.pendingFollowups = []` — 대기 중인 후속 이벤트 큐
- `G.compStrategy = null` — 현재 보상 전략 ('performance'|'equal'|'growth')

**후속 이벤트 시스템**:
- `FOLLOWUP_EVENTS` 별도 배열 (EVENTS와 분리, choices 없는 뉴스 형태)
- 데이터: `{id, headline, body, effects: {empHap, will, custSat, socVal, ...}, sourceEvent}`
- 이벤트 선택 시 `delayed` 필드가 있으면 `G.pendingFollowups.push({triggerDay: G.gDay + delayed.days, event: followupData})`
- `dayTick()`에서 `G.pendingFollowups` 순회 → `triggerDay <= G.gDay`인 항목 발동 → 뉴스 모달 표시 → 큐에서 제거

**기존 calcSKMSAlignment() 대체**:
- 기존 `calcSKMSAlignment()` 함수를 새로운 `G.skmsChoices` 태그 기반 계산으로 교체
- 5대 원칙별 선택 비율을 계산하여 가중 평균 → 0-100% 정합성

## Sub-project 2: 게임 시간 압축 + 드라마틱 피드백

### 2A. 시간 압축

| 항목 | 현재 | 변경 |
|------|------|------|
| 시나리오1 승리 | 30일 유지 | **15일** 유지 |
| 시나리오2 승리 | 20일 유지 | **10일** 유지 |
| 이벤트 간격 | `(40+rand*20)*60` ticks | `(20+rand*10)*60` ticks |
| 분기 회의 | 30일마다 | **15일마다** |
| 후보 갱신 | 30일마다 | **15일마다** |

체감 플레이 시간: 40분+ → **20-30분**, 이벤트 8-10개 경험.

**HUD 업데이트**: 승리 카운터 `/30d` 하드코딩 → 동적 임계값 (`G.scenario === 2 ? 10 : 15`)

### 2B. 즉각 반응 (선택 직후)

이벤트 선택 후:
1. **화면 플래시**: 전체 오버레이 0.3초 (긍정=`rgba(34,197,94,0.15)`, 부정=`rgba(220,38,38,0.15)`)
2. **직원 리액션**: 영향받는 직원 위에 이모지 말풍선 팝업 (😊/😡/😰), 2초 후 fadeOut
3. **지표 변동 숫자**: 게이지 옆에 `+12▲` (초록) 또는 `-8▼` (빨강) 텍스트, 위로 떠오르며 1.5초 후 소멸
4. **토스트 메시지**: 기존 유지 + 결과 요약 한 줄 ("구성원 행복 +15, 비용 -$500")

### 2C. 시간차 후속 이벤트 (연쇄 결과)

주요 이벤트 5-6개에 후속 이벤트 추가:

| 원래 이벤트 | 선택 | 후속 (N일 뒤) | 효과 |
|-------------|------|---------------|------|
| talent_scout | 연봉 인상 | 3일: "인재 유지 성공" | 뉴스만 (에이스 충성도+10) |
| talent_scout | 에이스 포기 | 3일: "팀 사기 저하" | empHap-10, 시니크 1명 발생 |
| burnout | 강제휴가 | 5일: "직원 복귀, 의욕 회복" | 번아웃 직원 will+20 |
| burnout | 무시 | 4일: "번아웃 확산" | 추가 2명 disengaged 전환 |
| ai_replacement | 감원 | 3일: "남은 직원 불안" | 전체 will-10, 퇴사 위험↑ |
| ai_replacement | 리스킬링 | 5일: "AI 역량 확보" | rookie 2명→ace, capability+15 |
| quiet_quitting | 1:1+커리어 | 4일: "변화의 조짐" | disengaged 1명→rookie |
| quiet_quitting | 무시 | 3일: "조용한 퇴사 시작" | 2명 퇴사 |

후속 이벤트 UI:
- 헤드라인에 "📰 후속" 배지
- 선택지 없음 — 결과 확인 후 "확인" 버튼만
- 원래 이벤트 이름 참조: "지난 '번아웃 위기' 결정의 결과입니다"
